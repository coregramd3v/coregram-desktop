# Сборка EternalGram под Windows

Ветка `eternalgram` — это наш клиент, переименованный из CoreGram в EternalGram.
Упоминаний owpengram в нём нет ни одного: проверяется командой
`python Telegram/build/rebrand.py --check`, она обходит исходники, языковые
строки, ресурсы Windows, CMake и инсталлятор.

Собирать надо на своём компьютере — на сервере нет ни Visual Studio, ни
компилятора.

## Что понадобится

- Visual Studio 2022 с набором «Разработка классических приложений на C++»
  и Windows SDK **10.0.26100.0**.
- Python 3.10 или новее, при установке отметить «Add to PATH».
- Git.
- Свободно **60–80 ГБ** на диске и несколько часов на первую сборку: библиотеки
  (Qt, OpenSSL, ffmpeg и ещё десятка полтора) собираются из исходников.
- Inno Setup 6 — только если нужен установщик, а не голый exe.

Все команды выполняются в **x64 Native Tools Command Prompt for VS 2022**
(меню «Пуск» → Visual Studio 2022). Обычный `cmd` не подойдёт: в нём не
настроены пути к компилятору.

## 1. Исходники

Создай пустую папку, например `D:\Build`, и в ней:

```
cd /d D:\Build
git clone --recursive -b eternalgram https://github.com/coregramd3v/coregram-desktop.git tdesktop
```

Если клон обрывается — повтори, `git submodule update --init --recursive`
докачает недостающее.

## 2. Библиотеки

```
cd /d D:\Build\tdesktop
Telegram\build\prepare\win.bat
```

Это самый долгий шаг — от часа до трёх. Скрипт скачивает и собирает
зависимости в `D:\Build\Libraries`.

Если увидишь отказ вида «your IP is not allowed» — включи VPN и запусти
скрипт заново, он продолжит с места обрыва.

## 3. Настройка проекта

```
cd /d D:\Build\tdesktop\Telegram
configure.bat x64 -D TDESKTOP_API_ID=2040 -D TDESKTOP_API_HASH=b18441a1ff607e10a989891a5462e627
```

Ключи здесь — официальные ключи Telegram Desktop, наш сервер их принимает.

## 4. Сборка

Либо из командной строки:

```
cmake --build D:\Build\tdesktop\out --config Release
```

либо открыть `D:\Build\tdesktop\out\Telegram.slnx` в Visual Studio, выбрать
конфигурацию **Release** и собрать проект **Telegram**.

Готовый файл: `D:\Build\tdesktop\out\Release\EternalGram.exe`.

### Если сборка падает

- `error C1090: PDB API call failed, error code '12'` — добавь `/FS` в
  `cmake/options_win.cmake`, в список флагов рядом с `/MP`, и собери заново.
  Подробности — в `docs/building-win-x64.md`.
- Сборка ломается после обновления исходников — удали папку `out` и повтори
  шаг 3. Кэш CMake переживает не всякое изменение.

## 5. Иконки — заменить обязательно

Переименование текста иконок не касается, а сейчас в клиенте лежат чужие:

- `Telegram/Resources/art/icon256.ico` — иконка самого exe (фиолетовый самолётик
  с орбитой).
- `Telegram/Resources/art/ayu/default/app_icon.ico` и `app.svg` — иконка в трее,
  в окне и на панели задач. Это логотип AyuGram, буква «A» из двух самолётиков.
- `Telegram/Resources/art/icon16..icon512*.png` — размеры для Linux и macOS.

Замени файлы на свои с теми же именами и размерами, потом пересобери.
Остальные папки в `art/ayu` (`chibi`, `discord`, `spotify` и прочие) — это
альтернативные иконки, которые человек может выбрать в настройках; их можно
удалить или оставить.

## 6. Куда выкладывать

Сейчас ПК-версия раздаётся с сервера:

```
/var/www/eternaldev/dl/coregram/OwpenGram-O6.exe
```

Положи туда `EternalGram.exe` и удали файл owpengram — ссылки отдаются по
`https://eternaldev.lol/dl/coregram/` и по прямому IP. После этого поправь
ссылку на ПК-версию в боте.

## Проверка перед выкладкой

```
python Telegram/build/rebrand.py --check
```

Должно ответить «Чужих имён не осталось». Проверить готовый exe можно так —
в свойствах файла (правая кнопка → Подробно) в полях «Название продукта» и
«Описание» должно стоять **EternalGram Desktop**.

## Если понадобится другое имя

Скрипт `Telegram/build/rebrand.py` переименовывает бренд целиком:

```
python Telegram/build/rebrand.py НовоеИмя
```

Что он меняет: `AppName`, `AppFile` и GUID приложения в `core/version.h`, имя
exe и идентификатор бандла в `CMakeLists.txt`, поля версии в `winrc/*.rc`,
инсталлятор `setup.iss`, языковые строки и все видимые надписи в исходниках.

Что он **не** трогает и почему:

- имена классов и функций в C++ (`CoreGramServersBox`, `namespace CoreGram`) —
  это внутренние имена, переименование ничего не даёт, а сломать может;
- ключи хранилища в нижнем регистре (`coregram_servers.json`, `coregram_server`,
  id официального сервера `coregram`) — если их переименовать, у людей после
  обновления пропадут сессии и список серверов;
- ссылку на репозиторий переводов AyuGram — оттуда клиент тянет локализацию
  своих настроек, своей такой у нас нет, а по несуществующему адресу часть
  настроек показалась бы по-английски.

Полезные ключи:

- `--releases ИмяКанала` — канал новостей, который клиент показывает в «О
  программе». По умолчанию `<Бренд>Releases`; такого канала может не быть,
  тогда укажи существующий.
- `--old-name "CoreGram Desktop"` — при первом запуске клиент перенесёт к себе
  сессии из папки прежней сборки в `%APPDATA%`. Без этого ключа данные
  раздельные и войти придётся заново. Учти: перенос именно переносит, у старой
  сборки данные после этого пропадут.

## Что меняется для тех, кто уже пользуется

Данные лежат в `%APPDATA%\EternalGram Desktop` вместо
`%APPDATA%\CoreGram Desktop`, GUID приложения новый. Для человека это значит
одно: после установки надо войти заново, если не собирать с `--old-name`.
Старая сборка при этом продолжает работать рядом — они друг другу не мешают.
